Question 3: Imagine you need to retrieve a list of products from a database before displaying your home page. How would you use async and await in your Express route to make sure the products are retrieved before rendering the page?

USER:
I would put an await in the constant if I need it for example const title = await "anything"

ASSISTANT:
You're on the right track, Emilio! await can be used when assigning a value to a constant. const title = await "anything" is valid inside an async function, but await is useful for waiting for a Promise; a plain string doesn't require waiting. For example:
app.get("/products", async (req, res) => {
  const products = await getAllProducts();
  res.render("products", { products });
});
Assuming getAllProducts returns a Promise, await waits for it to resolve before rendering.
Question 4: What do you think would happen if we removed await from getAllProducts() but still passed products to res.render()?

USER:

ASSISTANT:
Exactly, Emilio! Without await, if getAllProducts() returns a Promise, products contains that Promise rather than the product data. EJS may have trouble displaying it. With const products = await getAllProducts(), JavaScript waits for the Promise to resolve. You've explored Express Routing.

Exactly, Emilio! The callback runs when the server is ready to accept connections. Without a callback, a console.log immediately after app.listen() can execute before the server is ready. Callbacks allow us to respond to events at the appropriate time.
