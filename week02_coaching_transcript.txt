CREATE TABLE IF NOT EXISTS public.project_category (

ASSISTANT:
Excellent work, Emilio! 😊

Your SQL demonstrates a solid understanding of relational database design. Let's look at two important decisions you made.

1. Composite Primary Key
PRIMARY KEY (project_id, category_id)
This ensures that the same project-category combination cannot appear twice in your junction table.
For example, project 5 can belong to categories 2 and 3, but you cannot insert the combination (5, 2) twice.

2. Foreign Keys with CASCADE
ON UPDATE CASCADE ON DELETE CASCADE
These constraints maintain referential integrity.
- ON UPDATE CASCADE updates the matching foreign key values if a referenced ID changes.
- ON DELETE CASCADE automatically removes related records from project_category when a referenced project or category is deleted.
This helps prevent orphaned relationships in your database.

Let's explore your design decision.

You've explained both the practical benefit (fewer manual queries) and the database integrity benefit (preventing orphaned relationships).

One important detail is that ON DELETE CASCADE removes the corresponding records from project_category, but it does not delete the categories themselves when a project is deleted. This is exactly what you want for a many-to-many relationship.

My question: Why did you choose app.get("/categories", ...) instead of app.post("/categories", ...) for this route?

USER:
becouse post is for sencible data and not need to exposed

ASSISTANT:
Good thinking, Emilio! 😊 You're connecting HTTP methods with how data is sent and handled.
There's one important distinction to clarify:
- GET is primarily used to retrieve information from the server without changing data.
- POST is primarily used to submit data for processing, often to create a new resource.
POST is not automatically more secure than GET. Both methods should use HTTPS when transmitting sensitive information. POST typically sends data in the request body rather than the URL, but that doesn't make it secret.
In your application, GET is the correct choice because you're retrieving categories to display on a webpage, not creating or modifying them.
